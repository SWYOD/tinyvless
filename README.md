# tinyvless

Лёгкий VLESS-модуль для OpenWrt, заточенный под слабое железо — свой минималистичный Go-клиент
вместо sing-box/v2ray/xray, поэтому влезает и стабильно работает там, где обычные решения либо
не влезают по flash, либо съедают всю RAM. Задуман как альтернатива [Подкопу](https://github.com/itdoginfo/podkop)
и похожим инструментам — для тех, кому нужен VLESS-прокси прямо на роутере, а не на компьютере
за роутером.

Текущая (эталонная) сборка — Cudy LT300 v3.0: **16 МБ flash / 58 МБ RAM / 385 МГц одно ядро**.
Именно эти ограничения продиктовали архитектуру всего проекта: никаких тяжёлых прокси-движков,
агрессивный RAM-тюнинг, собственный парсер `vless://`-ссылок вместо общих библиотек.

## Две линейки

| Линейка | Статус | Что это |
|---|---|---|
| **Portable** | Текущая (v1–v12) | Автономный роутер со встроенным LTE-модемом — работает от повербанка, для поездок/дачи/там-где-нет-провода. Эталон — Cudy LT300 v3.0. |
| **Stationary** | Заявлено, в разработке | Роутер на постоянном питании, WAN по кабелю/WiFi — для дома, без зависимости от сотовой сети. Целевое железо ещё не определено. |

Полная хронология линейки Portable — [docs/CHANGELOG.md](docs/CHANGELOG.md), с версии v1 до
текущей v12. Каждый релиз в [GitHub Releases](../../releases) помечен линейкой в описании.

## Архитектура

- **tinyvless** (`src/tinyvless/`) — Go-клиент VLESS+WS+TLS (только WS/TLS, сознательно без
  Reality/XTLS — не подходит бюджету CPU этого класса железа). REDIRECT (TCP) + TPROXY (UDP)
  inbound, SOCKS5 для спидтеста, HTTP status-API.
- **tvled** (`src/tvled/`) — LED-демон: 3 задних индикатора уровня сигнала LTE по `AT+CSQ`,
  плюс событийный (без polling) индикатор связи на переднем двухцветном LED.
- **atcmd** (`src/atcmd/`) — AT-команды к модему: сигнал/оператор/тип сети, чтение и удаление SMS.
- **Панель** — LuCI-приложение + отдельная страница вне LuCI (быстрее грузится), общий JS-код
  через шимы. Микротюнинг (буферы, таймауты, лимиты — единый источник правды `microtun.conf`),
  спидтест (туннель vs напрямую), карточка «Клиенты LAN» (per-MAC bypass), бэкап/восстановление.
- **Селективный роутинг** — geo-набор российских подсетей (nftables set, агрегация до /18) +
  доменные списки (`direct_domains.list`/`tunnel_domains.list`) — в туннель уходит только
  реально нужный трафик, не всё подряд.
- **DNS** — split-DNS с DoH (обход DNS-отравления оператора), автодетект отравленных доменов,
  DoH-через-туннель для случаев, когда блокируют сам IP резолвера.
- **Self-healing** — `dns-watchdog` поднимает упавший dnsmasq и переприменяет роутинг после
  respawn'а tinyvless, без ручного вмешательства.

## Сборка образа

Требуется Docker:

```sh
cd firmware/ibwork/v10-work
./build-image-v12-magnumopus.sh          # дата тега — сегодняшняя, можно передать явно
```

Скрипт стейджит `firmware/ibwork/files/` (базовый слой) → накатывает `v10-work/{etc,www,usr}`
поверх → копирует бинари (`tinyvless`, `tvled`, `atcmd`) → гоняет OpenWrt ImageBuilder в
Docker-контейнере (`debian:bookworm`, `PROFILE=cudy_lt300-v3`).

`public-release-overlay/` накатывается сборками V12+ поверх `v10-work`: открытая WiFi-сеть без
пароля и пустой `VLESS_LINK` — так публикуемый образ не содержит чужих креденшлов по умолчанию.

## Ветки

- **`main`** — публичная, только вылизанные релизы. Продвигается мёрджем из `dev`.
- **`dev`** — рабочая ветка по умолчанию: новые фичи, новое железо, в том числе неудачные сборки.
- **`dev/<hardware-slug>`** — под-ветки нового железа от `dev` (например `dev/cudy-tr-usb-modem`
  для будущей поддержки USB-модем hotplug на Cudy TR-серии).

## Безопасность

Прошивка не содержит VLESS-ссылок или WiFi-паролей — они настраиваются через панель
(«Добавить профиль») и WiFi-настройки после первой прошивки. При локальных изменениях/форках
`VLESS_LINK` и пароли не должны попадать в публичную историю коммитов.

## Roadmap

- **Линейка Stationary** — прошивка для роутера без автономного питания/модема.
- **opkg/apk-пакет** — установка tinyvless-модуля поверх уже существующего OpenWrt без полной
  перепрошивки роутера целиком.
- Поддержка других моделей Cudy (TR-серия) — включая автоматический hotplug USB-модема.
- Reality/XTLS сознательно не поддерживается (только WS/TLS) — осознанный компромисс ради
  бюджета CPU на слабом железе.
- Пересборка и публикация очищенных v1–v11 как исторических GitHub Releases (сейчас в репозитории
  доступен только v12+ — см. [docs/CHANGELOG.md](docs/CHANGELOG.md) для текстовой хронологии
  более ранних версий).
- Долгосрочно — возможное сотрудничество с Cudy как производителем железа.
